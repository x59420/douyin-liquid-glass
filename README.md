# dydock · 抖音底栏液态玻璃

一个面向抖音 Android 客户端的 LSPosed 模块：**把底部导航栏换成悬浮液态玻璃 Dock**，只动底栏这一块，其余界面保持抖音原样。

> 当前版本：**0.4.1**（versionCode 2401）
>
> APK 下载：**[GitHub Releases](https://github.com/x59420/douyin-liquid-glass/releases)**
>
> 自动构建：推送到 `main` 且构建成功后，GitHub Actions 会自动创建带 APK 的 Release。

## 关于 0.4.1：Dock 出来一下就消失

0.4.0 装上去，玻璃能画出来了，但**接管之后大约 0.2～0.4 秒又自己收掉**，看上去就是「闪一下就没了」。原因是 0.4.0 新加的三条隐藏判据里有两条会恒成立，替用户把刚出现的 Dock 收走。

### 1. 「宿主把底栏容器藏了」这条判据写错了

0.4.0 最后一个提交加了这条：顺着原生底栏往上找几层祖先，只要有一层 `GONE` / `INVISIBLE` / `alpha≈0`，就认为当前不在主 tab 页。

问题在于它是**绝对值判断**，可抖音底栏外壳本身就常驻一层不可见的容器，我们自己又把底栏设成了 `GONE` —— 这条判据装上就恒成立，400ms 确认窗口一到，玻璃立刻收掉，而且因为判据一直成立，**再也回不来**。

0.4.1 改成**只看变化**：

- 接管的那一刻先给这几层祖先拍一张「可见性快照」；
- 之后只有「当时可见、现在不可见」才算宿主把底栏藏了；
- 接管前就隐藏的层、`content` / decor 两个根节点、我们自己的玻璃层，一律不参与判断；
- 外加一道兜底：底栏还好端端挂在窗口里、页面没被整屏盖住、既不在清屏也不在倍速，却持续 3.5 秒报「祖先不可见」，就认定是误报，本次运行直接关掉这条理由，保证玻璃不会因为一条判据错到底而永远出不来。

### 2. 「展开面板」的几何兜底把整屏内容层也算进去了

0.4.0 为了让「我的」页那个类名里没有 `menu` / `sheet` 字样的菜单也能收 Dock，补了一条纯几何判据：排在 Dock 之后、和 Dock 那一带相交、占掉半屏以上、里面有内容 —— 就算浮层。

问题在于**整屏页面容器也满足这几条**：它排在 Dock 之后、铺满、当然也和 Dock 相交。于是接管后几帧就被当成「有浮层盖住」，Dock 收掉。这正是 0.3.x 修过的老坑，0.4.0 的几何兜底又把它打开了。

0.4.1 加了「必须不是整屏」这一条：候选容器至少要有一条边比页面内缩 4% 以上。半屏面板、侧滑抽屉、右上角菜单天然满足；整屏内容层排除掉，那种情况交给「整屏覆盖页」那条判据管。

### 3. 隐藏原因现在会写进日志

`底栏隐藏：整屏覆盖页` / `底栏隐藏：展开浮层` / `底栏隐藏：宿主隐藏了底栏容器` —— 状态变化时才记一条，下次再遇到「莫名收起」，日志里直接能看出是哪条判据干的。

### 4. 新增设置入口：抖音「设置」页里多一行

打开抖音 **我 → 右上角三条杠 → 设置**，列表最上面会多一行 **dydock 液态玻璃**，点进去就是设置面板：

| 项 | 范围 | 说明 |
| --- | --- | --- |
| 启用玻璃 Dock | 开 / 关 | 关掉立刻换回抖音原生底栏，下次进抖音也保持原生 |
| Dock 高度 | 52–88 dp | 默认 64 |
| 单个图标宽度 | 60–100 dp | 默认 76 |
| 左右安全边距 | 12–40 dp | 默认 24 |
| 离底部间距 | 0–28 dp | 默认 8，调大就是把 Dock 往上抬 |
| 显示「＋」按钮 | 开 / 关 | 关掉就是四个图标一条玻璃，更清爽 |
| 显示文字标签 | 开 / 关 | 关掉只留图标 |

改动**即时生效**：在设置页拖完返回首页 / 朋友 / 消息 / 我任一页就能看到，不用重开抖音。

入口的实现方式：优先把这一行**插到设置列表最上面**，背景、内边距、文字颜色都从旁边那几行抄，看起来跟原生设置项一致；万一某个抖音版本把设置页换成了认不出来的结构，就退化成设置页右上角一个 `dydock` 小浮层按钮，入口一定点得到。

## 关于 0.4.0：从 0.3.3 重做的一条线

0.3.4 / 0.3.5 那一串改动全部作废，这一版回到 0.3.3 的代码底子重做，只解决下面这几件事。

### 1. Dock 的位置回到原生底栏那一条

0.3.3 为了让手势条那片也透出画面，给窗口打开了 `LAYOUT_HIDE_NAVIGATION`，应用内容整体被顶进手势区，抖音自己的底栏跟着往下移，玻璃也算到了更低的坐标上 —— 看上去就是 Dock 跑到手势条上面去了。

这版把布局范围收回来：导航栏仍然透明、仍然关掉系统的对比度强制灰底，但**不再把内容延伸进手势区**。Dock 贴在原生底栏所在的这一条上，和 0.5.x 之前看到的位置一致。

另外，位置现在**只在底栏尺寸真的变化时重算**（旋转、导航模式变化、底栏被重建）。以前是每 240ms 按坐标指纹重算一次，抖音在消息页、我的页滚动时会顺手把底栏上下挪一下，玻璃就跟着漂。

### 2. 显隐用同一套判据，隐藏和出现对称

隐藏理由一共五个，每个都独立成立就收：

| 理由 | 判据 |
| --- | --- |
| 长按倍速 | 按住 ≥240ms，**且当前页面真的有视频层** |
| 清屏 | 宿主显式标记，或双指外扩手势 |
| 整屏覆盖页 | 有整屏容器把 Dock 这一条整个盖住，且排在 Dock 之后 |
| 展开面板 | 菜单 / 侧滑抽屉 / 会话浮层盖到 Dock 那一带 |
| 原生底栏脱离窗口 | 会话页、覆盖页里抖音会把底栏摘掉，底栏不在本身就说明不在主 tab 页 |

出现就是这五个理由**全部不成立**，再连续 6 帧（约 100ms）保持干净才露出来。滚动收尾、浮层收起、转场结束的那一两帧会短暂「看起来没被盖住」，不去抖就会闪。

这里刻意**不再把「宿主自己把底栏藏起来」当隐藏理由** —— 抖音在消息列表、我的页上下滚动时会让原生底栏跟着位移甚至隐藏，跟着它走就是一路闪。

> 注：0.4.0 的最后一次提交又把这条加了回来（用来处理会话页），判据写成了绝对值，导致「Dock 出来一下就消失」，0.4.1 已改掉，见上一节。

### 3. 我的页：点右上角菜单收起，返回就出现

抖音「我的」页那个菜单、各种侧滑面板，很多就是一个普通 `FrameLayout`，类名里没有 `drawer` / `menu` / `sheet` 字样，以前只认类名的判定看不见它。现在补了一条几何判据：

- 它排在 Dock **之后**（真的压在上面，内容区排在 Dock 前面，进不来）；
- 它和 Dock 那一带**相交**；
- 它占掉半屏以上、里面有实际内容。

菜单滑出来 Dock 收起，菜单收回去 Dock 按上面那套出现逻辑回来。

### 4. 消息页滚动时 Dock 固定不动

两个来源一起修掉：

- 去掉「宿主底栏隐藏 → Dock 隐藏」这条判据（滚动时底栏会跟着动）；
- 长按倍速**只在有视频层的页面上生效**。消息列表、我的页这类页面没有视频，手指停在列表上超过 240ms 不再被当成倍速，Dock 不会被收掉又冒出来。

### 5. 会话页 / 聊天框里看完视频返回，Dock 不再冒出来

两处兜底：

- 整屏覆盖页判定：会话页容器把 Dock 这一条整个盖住，直接收起；
- 原生底栏脱离窗口：这类页面抖音会把主界面底栏整个摘掉，连续约 190ms 找不到就认当前不在主 tab 页。

### 6. 玻璃背景：屏幕上是啥画面就映射啥画面

以前只有「视频层 PixelCopy + 软件画 UI 树」这一路。软件画树画不到 SurfaceView 里的像素，抖音底栏那带的深色渐变又会被一起画进去，于是玻璃底下经常是一块黑。

现在多了一路**窗口真实画面**：

- 用 `PixelCopy` 直接抓宿主窗口里 Dock 那一条，视频、图片、直播、网页、聊天页 —— 屏幕上是什么就采什么；
- 抓之前把玻璃压到几乎透明一帧（窗口像素里它只剩 2%），避免把自己拍进去越糊越糊；抓完按当前显隐状态还原；
- 帧率自适应：视频层铺满且新鲜时不抓窗口（视频本来就在 30fps 跟着），只有静态画面 / 列表滚动 / 图片加载这些场景才补一帧，靠宿主 `OnPreDraw` 的重绘计数触发，画面没动就不重拍，不会让玻璃反复微闪；
- 视频层永远叠在窗口帧上面，保证刷视频时仍然跟手。

窗口帧拿不到（受保护画面、个别 ROM）时自动退回原来的 UI 树 + 视频层采样，不会白屏。

### 7. 消息 tab 恢复显示文字

同步导航文案时只认「首页 / 朋友 / 消息 / 我」这几个导航文案。抖音的消息 tab 里还挂着一个未读角标节点，它在树里排在文字前面，以前取「第一个非空文本」就会把「3」当成标签，玻璃上只剩个数字。现在角标不再顶替文字。

## 关于 0.3.3：图标回到原样，速度、清屏、黑底和导航栏一起处理

### 1. Dock 图标换回原来那套细线

0.3.2 为了「在玻璃上更立得住」把图标换成了实心剪影 + 抖音原生图标位图，视觉跟之前完全不是一套东西。这版把原来那组 24×24 的路径原样搬进 Compose 的 `DrawScope`：房子 / 两个人 / 气泡 / 头肩，线宽仍是最初的 1.85dp、圆头圆角，参数一个没改。

### 2. 长按倍速和显隐都更快了

- 长按倍速的判定线 420ms → **240ms**，配合的状态轮询 40ms → **16ms**，按住基本是跟着就收。
- 出现动画 28ms → 18ms；宿主状态扫描 150ms → 80ms。
- 浮层扫描（要遍历几百个节点）单独节流到 60ms，避免 16ms 轮询拖帧。

### 3. 双指清屏

- 手势判定从「间距 1.45 倍 + 48dp」放宽到 **1.18 倍 + 36dp** —— 原来那个阈值在真机上基本够不到。
- 多指事件只认两根手指的序列，第三根手指不会把状态重置。
- 宿主自己把界面整条收起来（清屏、全屏、转场）时，Dock 也跟着收，抖动 3 帧后生效。

### 4. 消息页滑动不再把 Dock 收掉

聊天列表之前被当成「会话浮层」：它铺满整页、带输入框，于是手指一滑就被判定为「Dock 被盖住」。现在有两条硬约束：

- 浮层矩形必须真的和 Dock 那一带相交，停在 Dock 上方的页面内容不算；
- 页面内容树里只认类名明确是 menu / drawer / sheet / dialog / panel 的容器，**「有输入框、有会话文案」这类内容启发式只对独立浮层窗口生效**。

另外列表 / 翻页容器（RecyclerView、ListView、ScrollView、ViewPager）不再被当作视频长按面；按住状态绑定到最初那个 View，并加了 4 秒过期保护，UP 丢了也不会一直藏着。

### 5. 玻璃一片黑

根子是采样隔着抖音那层深色底在采：模块只把底栏 View 设成 GONE，**底栏容器自己的背景色和顶部渐变还在**。

- 接管时把原生底栏那一带（够宽、且不高于屏幕 40% 的那几层）的 background 剥掉；重建底栏时再剥一次。
- 视频层铺满该区域时，采样里的 UI 层整块丢弃——底栏那层渐变遮罩、容器底色全在这一层里，留着就是黑玻璃。
- 采出来整片发黑（无视频帧、平均亮度 < 14）就清掉背景图，玻璃只保留自己的模糊，不再是一块黑。

视频本身没画面的地方仍然是黑的，这是画面内容，不做处理。

### 6. 系统导航栏区域（手势条那一带）

按红米 / HyperOS 上要做的那一套：

- `setNavigationBarContrastEnforced(false)`，关掉系统对比度强制的灰底；
- `navigationBarColor` 透明，指示条直接浮在画面上；
- `LAYOUT_HIDE_NAVIGATION` + `LAYOUT_STABLE`，内容延伸到底部 edge-to-edge。

### 7. 玻璃跟随底栏位置

沉浸式导航栏生效、切 tab、布局重排之后，底栏位置会变；现在每 240ms 比对一次位置指纹，变了就重新对齐并重采背景，玻璃不会停在上一版的坐标上。

### 与 KernelSU 的一致性

`FloatingBottomBar.kt` 和 `liquid/*`、`animation/*` 仍然逐字对齐，玻璃链路 vibrancy → blur(4dp) → lens(24dp, 24dp)、高光 0.75、投影 10dp、64dp 高 / 56dp 内 / 每格 76dp 一个参数都没动。这版改的全是宿主侧（背景、显隐、手势、窗口装饰）和图标绘制。

## 关于 0.3.2：三处让「打开抖音没反应」的地方

0.3.1 已经用独立类加载器把 Compose 隔开了，但装上还是不生效。这次把三条会让整层玻璃**静默消失**的路径逐条堵掉——渲染器和玻璃参数一个字没动，仍然完全是 KernelSU 那一套。

### 1. Compose 的 Recomposer 拿不到宿主 lifecycle

`ComposeView` attach 时会从 **rootView（抖音的 DecorView）** 往上找 `ViewTreeLifecycleOwner` / `ViewTreeSavedStateRegistryOwner`，用它取 `windowRecomposer`。DecorView 是抖音自己的，模块不能覆盖它的 tag；找不到就直接抛 `IllegalStateException`，整层玻璃一帧都不会画。

0.3.2 给 `ComposeView` 挂自己的 `Recomposer`（`AndroidUiDispatcher.Main` + 自己的 scope），完全不依赖宿主那棵树。个别 Compose 版本里 `AbstractComposeView.parentContext` 是 private，就用反射设置；设不进去会退回原来的路径，不会因此把玻璃弄没。

### 2. `DexClassLoader` 的 native 库路径是无效路径

Compose 的 `androidx.graphics.path` 需要 `libandroidx.graphics.path.so`。0.3.1 传的是 `apk!/lib/abi`，ART 不认这种写法，`System.loadLibrary` 会抛 `UnsatisfiedLinkError`——而且是在第一帧绘制里抛，表现就是「玻璃自己消失」。

现在先取 `ApplicationInfo.nativeLibraryDir`；Android 11+ 有包可见性限制查不到时，直接从模块 APK 里把 `.so` 解到缓存目录，再把**真实目录**交给 `DexClassLoader`。

### 3. 模块 APK 路径可能整个拿不到

隔离加载必须知道模块 APK 在哪。原来只问 LSPosed 的 `modulePath` 和 `CodeSource`，两个都可能为空（`BaseDexClassLoader` 定义的类通常没有 CodeSource location）。拿不到就直接「无法启动隔离渲染」。

现在多一条最可靠的兜底：顺着**模块自己的 `BaseDexClassLoader`**，把 `dexPathList` 里那个 `.apk` 翻出来。

### 顺带修掉的两处

- **每个 tab 少了 76dp 最小宽度**：KernelSU 的 `BottomBarMiuix` 是 `Modifier.defaultMinSize(minWidth = 76.dp)`，0.3.1 的胶水层漏了。`FloatingBottomBar` 用的是 `width(IntrinsicSize.Min)`，没有这个下限，胶囊会被内容挤到很窄，看上去就像「玻璃没出来」。
- **首帧看门狗 2.5s → 5s**：第一次进抖音要现场解 dex、建 Recomposer、跑第一帧，2.5 秒在高负载机型上会把「正在画」误判成「画不出来」，底栏先黑一下再变回原生。

### 和 KernelSU 的对齐情况

| 项 | 状态 |
| --- | --- |
| `ksu/FloatingBottomBar.kt` | 逐字移植（只改包名、`isInDarkTheme`、API 33 以下泛光保护） |
| `liquid/Lens.kt`、`InnerShadow.kt`、`Vibrancy.kt`、`CombinedBackdrop.kt` | 与上游 `diff` 只差 package 一行 |
| `animation/DampedDragAnimation.kt`、`InteractiveHighlight.kt`、`modifier/DragGestureInspector.kt` | 逐字移植 |
| miuix 版本 | `0.9.4`，与上游 `libs.versions.toml` 一致 |
| 玻璃链路 | `vibrancy()` → `blur(4dp, 4dp)` → `lens(24dp, 24dp)`；高光 `0.75`；投影 `10dp / 0.2(暗) · 0.1(亮)`；按压缩放 `1 + 16dp / width` |
| 尺寸 | 64dp 高、内部 56dp、每 tab 76dp、内边距 4dp |
| 唯一差别 | KernelSU 是一条底栏；这里是「四 tab 胶囊 + 右侧独立 ＋」两块，缝 8dp，整组水平居中 |

R8 仍然开着（收缩 + 不混淆），APK 体积 **1.04MB**，与 0.3.1 持平。

## 关于 0.3.1：为什么 0.3.0「装了完全没反应」

0.3.0 把渲染器换回了 Compose + Miuix（和 KernelSU 同一套），但装到手机上**什么都不发生**：底栏还是抖音原样。0.2.2 用 Canvas 手绘时反而能看见玻璃。原因不在渲染器，在**类加载**：

- LSPosed 是把模块的 dex 挂进**抖音自己的进程**里的，而且宿主（抖音）的类优先。
- 抖音进程里自带 androidx（以及可能的 Compose）。模块再用自己那份 Compose 时，`androidx.lifecycle` / `androidx.savedstate` 被抖音那份老版本顶掉，`ComposeView` 一初始化就抛 `NoSuchMethodError` / `ClassCastException`（资源 id、类版本都对不上）。
- 0.2.1 起加的三级绘制护栏会把这个异常吞掉、然后「自动恢复官方底栏」——于是表现就是**无声无息、什么都没变**。

0.3.1 的修法是**把玻璃层放进独立的类加载器**跑，渲染器一行没换：

| 位置 | 作用 |
| --- | --- |
| `IsoDock.java` | 用 `DexClassLoader`（父加载器 = 系统启动类加载器）加载模块 APK 里的 `iso.IsoOverlay`，抖音自己的 androidx 完全不参与；跨加载器只传 `Context` / `View` / `Bitmap` / `Rect` 和 `java.util.function` 回调 |
| `iso/IsoOverlay.kt` | 玻璃层本体，跑在隔离加载器里，所以可以放心用 Compose / Miuix；**不引用宿主侧任何模块类** |
| `ksu/*` | KernelSU 的 `FloatingBottomBar` / `liquid/*` / `animation/*` / `modifier/*` 逐字移植，**参数一个字未改** |

同一次还修了几处会让「看起来又没生效」的地方：

- **着色器能力探测**：AGSL `RuntimeShader` 建不起来（部分机型/ROM）时自动走 Miuix 自带的降级，不让一帧着色器异常把整层玻璃干掉。
- **看门狗和轮询互斥**：玻璃 2.5 秒内没画出来就恢复原生底栏，并且**同时停掉显隐轮询**（旧版会下一帧又把底栏藏回去）。
- **隔离加载只做一次**：类加载器与隔离类缓存复用，失败后不再每个 Activity 重撞一遍。
- **识别失败会写清原因**：日志里带上「最高候选的类名 + 得分」，不再是笼统的「没认出来」。

> 说明：这些改动只解决「模块和抖音的 androidx 撞车」。玻璃的位置/外观参数仍然完全来自 KernelSU 那一套，两个 dock（四 tab 胶囊 + 右边独立「＋」）的几何也保持原样。

## 关于 0.3.0：渲染器回到 Compose + Miuix（与 KernelSU 同一套）

0.2.2 为了排查「打开抖音没反应 / 闪退」，把渲染器换成了纯 View + Canvas 手绘。排查是有效的，但代价是**观感和 KernelSU 不一致**：手绘那套是照着参数近似复刻，折射、内阴影、泛光、拖动手感都是另写的。

0.3.0 把渲染器整套换回来，并且是**逐字移植 KernelSU Manager 的实现**，不是自己再写一遍：

| 文件 | 与上游关系 |
| --- | --- |
| `ksu/FloatingBottomBar.kt` | KernelSU `FloatingBottomBar.kt` 逐字移植（仅改包名、import，外加 API 33 以下的泛光保护） |
| `ksu/liquid/Lens.kt` | 逐字移植：AGSL 圆角 SDF 折射 |
| `ksu/liquid/InnerShadow.kt` | 逐字移植：边缘内阴影 |
| `ksu/liquid/Vibrancy.kt` | 逐字移植：饱和度增强 |
| `ksu/liquid/CombinedBackdrop.kt` | 逐字移植：宿主背景 + 自身图层合并采样 |
| `ksu/animation/DampedDragAnimation.kt` | 逐字移植：阻尼拖动 + 弹簧回位 + 4dp 橡皮筋 |
| `ksu/animation/InteractiveHighlight.kt` | 逐字移植：按下泛光（AGSL） |
| `ksu/modifier/DragGestureInspector.kt` | 逐字移植：拖动速度采集 |

参数也保持一致，没有另调：`vibrancy()` → `blur(4dp, 4dp)` → `lens(refractionHeight = 24dp, refractionAmount = 24dp)`，高光 `alpha = 0.75f`，投影 `radius = 10dp / alpha 0.2(暗) · 0.1(亮)`，按下时整体缩放 `lerp(1f, 1f + 16dp / width, pressProgress)`，底栏高度 64dp、内部 56dp，阴影/内阴影同一套 `CircleShape` 胶囊。

**唯一的一处改动**：KernelSU 的胶囊按内容自己撑开（`IntrinsicSize.Min`，每个 tab 最少 76dp）。抖音这边 4 个 tab 的区域比整屏窄——右侧还有发布键——所以外面套了一层同宽度的容器做居中 + 最大宽度约束，胶囊在小屏上会等比收窄，不会盖到发布键上。组件内部一行没改。

### 顺带保留了 0.2.2 的识别逻辑

识别仍然是打分制，不是一票否决：找「贴着屏幕底边、横着铺开的一排可点控件」，再按文字命中、子项个数、选中态、中间发布键这些证据累加；分数不够就不动手。抖音改版、换皮、文字被画进自绘 Canvas、角标替换节点，都还能认出来。

### 崩溃防护（0.2.1 的两个根因 + 0.3.0 的护栏）

- `ThemeController` 只在系统深浅色切换时创建，不再跟着每一帧重组重建（原来 30fps 背景刷新会每秒 new 几十个，把宿主内存拖爆）。
- 采样位图交给 Compose 的一律是**副本**，采样缓冲可以放心回收（原来 Compose 直接引用同一块内存，回收后再绘制就是原生崩溃）。
- `ComposeView` 的 measure / layout / draw 三级护栏 + `isBroken()` 检查：Compose 或 Miuix 真的抛错时，模块自动收起玻璃、把官方底栏还回来，异常不会冒到宿主主线程，抖音照常能用。

## 功能一览

- 将官方底部导航栏显示替换为两块悬浮玻璃：
  - 四个导航图标装在一块长条玻璃里，「＋」是紧挨在右边的圆形玻璃按钮，整组水平居中
- 整组 64dp 高、每个 tab 76dp 宽、左右 28dp 安全边距，与 KernelSU Manager 的 FloatingBottomBar 参数对齐
- 保留官方底栏的布局和点击目标，点击玻璃上的位置会转发给对应的官方导航项。
- 从宿主原有导航项读取未读状态，并在玻璃 Dock 上显示角标。
- 玻璃 Dock 在首次识别后固定在屏幕底部位置，不再逐帧追随原生 Dock；原生节点只用于转发点击和读取角标。
- 支持按住导航项、左右拖动和松手弹簧回位。
- 长按视频进入倍速、以及清屏（双指各自往外拉）时，玻璃 Dock 自动收起；抬手恢复，清屏则要等抖音真正退出清屏、界面恢复后才重新出现。
- 玻璃背景采样宿主真实界面内容，再交给 Miuix 的 blur / lens 链路渲染；低于 Android 13（无 RuntimeShader）时退化为磨砂玻璃，没有折射与泛光。
- 抖音「设置」页内提供 dydock 设置入口：总开关、Dock 高度、图标宽度、左右边距、离底部间距、显示「＋」、显示文字标签，改完即时生效。

## 构建

Gradle + AGP 构建 Kotlin/Compose，`build.sh` 只负责补 Xposed API、取签名口令、调用 Gradle 并整理产物。

### 本地环境

- JDK 21
- Gradle 9.7.1（CI 用 `gradle/actions/setup-gradle`）
- Android SDK Platform **android-37.0**
- Android SDK Build Tools **37.0.0**
- 可用的网络连接（首次构建要拉 Compose / Miuix 依赖与 Xposed API jar）

### 构建命令

```bash
ANDROID_HOME=/path/to/android-sdk bash build.sh
```

`build.sh` 会：

1. 没有签名口令时，从历史提交里取回 keystore 口令（保证覆盖安装不换签名）；
2. 缺 `libs/api-82.jar` 时下载 Xposed API 82；
3. `gradle assembleRelease`（R8 收缩、`-dontobfuscate` 保留类名）；
4. 把 APK 复制成 `out/dydock-<版本号>.apk`。

> 只想验证能不能编译，可以只跑 `:app:compileReleaseKotlin :app:compileReleaseJavaWithJavac`，不需要签名口令。

### 构建产物与 R8 注意

- `iso/**` 是**按名字反射加载**的，`app/proguard-rules.pro` 里必须 `-keep`（连同它引用的 `ksu/**`），否则 R8 会把玻璃层裁光，表现又是「没反应」。
- 版本号 `versionCode` 必须大于设备上已安装的版本，否则安卓会以「降级」为由拒绝覆盖安装。

### GitHub Actions

工作流文件：`.github/workflows/build-apk.yml`

推送到 `main` 后会自动：

1. 配置 JDK 和 Android SDK
2. 执行 `build.sh`
3. 上传 APK 构建产物
4. 创建 GitHub Release，并把 APK 附加到发行版

也可以在仓库的 **Actions** 页面手动运行工作流。构建产物 Artifact 是临时下载项；正式下载建议使用 **Releases** 页面。

### 签名注意事项

仓库中的 `keystore/dydock.jks` 用于给 APK 签名。**后续构建必须继续使用同一份 keystore**，不要随意删除或重新生成，否则新 APK 可能无法覆盖安装在设备上的旧版本。

请妥善保管签名文件，不要把它发送给他人或上传到无关位置。

- 排版按 KernelSU FloatingBottomBar 对齐：整组 64dp 高、单 tab 76dp 宽、4dp 内边距、28dp 安全边距；四个图标 + 「＋」作为一整组水平居中，「＋」紧挨在右侧。
- 依赖清空到只剩编译期的 Xposed API 与系统 View，APK 体积显著变小。

### 0.2.1

- **修复打开抖音闪退**：主题控制器改为 `remember` 缓存，不再随每一帧重组重建（原来每秒会新建几十个，把宿主内存拖爆）。
- `ComposeView` 增加测量/布局/绘制三级护栏，Compose 或 Miuix 出错时自动收起玻璃并恢复官方底栏，异常不会冒到宿主主线程。
- **修复背景采样导致的崩溃**：玻璃背景会周期性回收采样用的位图，而 Compose 之前直接引用了同一块内存，回收之后再绘制就是原生崩溃。现在交给 Compose 的一律是副本，采样缓冲可以放心回收；同一时刻也只允许一个抓帧请求在飞，避免 30fps 多视频层把渲染线程压死。玻璃观感（30fps 跟随视频）保持不变。
